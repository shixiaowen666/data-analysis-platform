## 一、阻断级（当前状态 rebuild 会失败 / 结果错误）

### 1. rebuild 因 41 张表缺 description 直接抛异常 ☐
- 位置：`webapp/app/services/metadata_processor.py:498-500`
- 现象：`database_meta.json` 中 41/70 张表 description 为空，`table_enhancement` 只有旧数据集 8 张表，`POST /api/metadata/rebuild` 必然在 `view_net_local_elec` 处 `ValueError`。
- 佐证：`index_cache.json` 记录 hash `4bd936…`，当前文件 hash `4ae07a…`，上次成功重建后文件已改、再未成功重建。
- 建议：非空硬校验降级为 warning，缺失时用 `display_name` 兜底。

### 2. `domain_knowledge.json` 是旧项目（南方电网调度）残留，正在污染当前数据集 ☐
- 位置：`webapp/data/domain_knowledge.json`
- `topic_definitions` 7 个主题的 `tables` 全部不存在，但 `_process_topics` 按 `metric_keywords` 子串仍会把 35 个指标绑到"发电量统计"、8 个绑到"负荷与备用"；Path B 命中后整包灌入候选（×0.9）。
- `dim_display_name_map` 会把 `month/quarter/weekofyear/year` display_name 覆盖为"月份/季度/自然周/年度"，与 `gen_database_meta.py` 生成的名称不一致。
- `derived_dependency_rules` 全是"跳闸/重合闸"，Path D 形同虚设。
- 建议：清空或按当前领域重写。

### 3. 代码内硬编码的旧领域规则仍在生效 ☐
- 位置：`metadata_processor.py:52-115`（`METRIC_SYNONYMS_PATTERN` / `UNIT_INFERENCE_RULES` / `DIM_VALUE_SYNONYMS`）
- 单位推断给 10 个无单位指标强加错误单位：`用电量最大负荷→MWh`、`已归档工单的总处理时长→min`；真实单位集合（亿千瓦时/万kWh/户/条/座…）一个都不在规则里。
- 别名规则往 L1 字典注入 `电量→年累计发电量`、`发电→光伏用户发电量`、`装机→地方电厂装机容量` 等极短多义映射。
- 建议：挪到配置文件并按当前领域重写，或删除交给 AI 补全流程。

### 4. 数据模型缺陷：同一 metric_code 跨表多义被压成一个实体 ☐
- 位置：`metadata_processor._process_metrics / _infer_mappings`（以 code 去重）
- 38 个列名在不同表语义不同：`ll_rate`=分区/分压/分台区/分线线损率（7 表）、`power`=用电负荷/行业用电量/业扩用电量/用电量（5 表）、`electricityvalue`=转供电量/线路供电量/供电量（5 表）、`usercount`、`user_num`。
- 后果：只有一个"分区线损率"实体，embedding 文本无"分压"字样。测试集 11 条用例（#46/49/54/60/84/85/135/138/188/191/215）期望指标被迫留空。
- 建议：实体主键改为 `(table, code)`，或 embedding_text 拼入各表列描述；这是召回上限问题，不能靠调参。

## 二、高风险（能跑，生产会出事）

### 5. 密钥泄漏 ☐
- `webapp/README.md:103/539/545` 明文 DashScope key，已入 git 历史并推到 GitHub → **立即轮换**。
- `Dockerfile:6` `COPY .env /code/.env` 把密钥烤进镜像层 → 改为运行时注入。

### 6. 管理接口零鉴权 ☐
- `/api/metadata/rebuild`（可传任意 `raw_path`）、`PUT /api/metadata/database-meta`（无 schema 校验直接覆盖）、`/api/prompts/*`、`/api/recall/config/*`、`/api/metadata/sync`（连生产库）全部无认证，无 CORS 配置。
- 建议：API-Key 依赖 + 管理/查询接口分离。

### 7. rebuild 非原子，重建窗口内线上返回错误结果 ☐
- `MetadataProcessor.process` 首步 `DELETE FROM meta_*`（`:258`），随后编码数分钟；期间内存 FAISS 索引 id 指向已删行，`SlimExporter._query_in` 查空；`DELETE` 不重置自增，新旧 id 错位。
- 全项目 14 处文件写入无一处 tmp+`os.replace` 原子写。
- 建议：影子表/版本号一次性切换，或 rebuild 期间返回 503。

### 8. 时间词剥离正则会切碎查询 ☐
- `recall_service.py:95-104`，实测：`2026年7月1日与6月15日相比 → 与 15日相比`；`上个月` 不匹配。
- 建议：抽为可配置模块 + 单测。

### 9. 硬编码 IP/端口/路径 ☐
- `.env`：`RERANK_API_BASE_URL=http://192.168.3.49:1234`、`JAVA_SYNC_BASE_URL=http://127.0.0.1:8080`、`LOG_DIR=/code/logs`（本地不可用）。
- `index_cache.py:17`、`batch_test_service.py:316`、`meta_sync.py:35` 各自 `Path(__file__)...` 拼 data 路径，绕过 `config.DATA_DIR`。
- `description_sync.py:25` `"test_"` 前缀与 `gen_database_meta.py` 靠魔法字符串暗中约定。

### 10. LLM 客户端无超时 ☐
- `llm.py:17` 未设 timeout（SDK 默认 600s）× tenacity 3 次重试，最坏挂 30 分钟；与 embedding 客户端（60s）不一致。

### 11. 并发/状态管理 ☐
- `RecallService.recall` 每请求新建 `ThreadPoolExecutor(4)`；批测并发 10 × 意图拆分 4 = 瞬时 160 线程。
- `endpoints._state`、`batch_test_service._RUNS`、各单例全是模块级全局 → 只能单 worker。
- `meta_sync.py:136`、`batch_test_service.py:372` services 反向 import `app.api.endpoints._state`。
- `_rebuild_lock` 不覆盖 `meta_sync(rebuild=True)` 路径，两者可并发。
