# 智能问数召回服务 v2.0 —— 使用手册与接口说明

> 适用版本：`recall-embedding` v2.0（实体级增量向量化 + Agent 范围召回）
> 配套文档：《对外接口变更说明》见本文第 6 章；《上游接口契约》见第 4 章。

---

## 1. 系统概述

召回服务把上游"数据管理模块"维护的 **表 / 指标 / 维度 / 维度值 / 业务知识** 转成向量，供智能问数在线阶段按自然语言问题召回相关元数据。v2.0 的核心变化：

| 目标 | v1.x | v2.0 |
|---|---|---|
| 更新一个指标/维度/表 | 全量重新向量化 | 只重编该实体及受影响的父实体（`text_hash` 差分） |
| 创建 Agent | — | 只登记范围，**零向量化** |
| 向量粒度 | 按 database_meta 整体 | 原子实体，`entity_key` 稳定，`faiss_id` 永不回收 |
| 范围检索 | 无 | `agent_id` / 内联 `scope` → FAISS `IDSelector` 预过滤 |
| 同码不同义指标 | 混为一条 | `metric:{code}` + `metric:{code}#{hash}` 变体 |

### 1.1 实体键规则

| 实体类型 | entity_key | 说明 |
|---|---|---|
| table | `table:{table_name}` | |
| metric | `metric:{metric_code}`；变体 `metric:{metric_code}#{sha1(列描述)[:8]}` | 同一 code 在不同表里列描述不同则拆变体 |
| dimension | `dimension:{dimension_code}` | |
| dim_value | `value:{dimension_code}:{value}` | |
| knowledge | `knowledge:{knowledge_id}` | 业务知识 / 派生指标 |
| topic | `topic:{name}` | 主题 |

### 1.2 变更传播规则（哪些实体会被重新编码）

| 变更 | 自身 | 传播到 |
|---|---|---|
| 指标 / 维度 / 表 **description** 变化 | ✔ | 无 |
| 指标 / 维度 **name / aliases** 变化 | ✔ | 所属表（表文本含指标名列表；文本未变则只校验 hash，不编码） |
| 维度 name 变化 | ✔ | 该维度下所有维度值 |
| 维度值 新增 / 删除 | ✔（值本身） | 所属维度（维度文本含值列表） |
| 表 columns 变化 | ✔ | 表内指标 / 维度的 `legal_tables` 重算（元数据更新，多数不编码） |
| 表删除 | 删除 | 相关指标 / 维度 `legal_tables` 去掉该表；不再被任何表引用的实体保留为孤儿（仍可召回） |
| 注册 / 修改 Agent | — | **不触发任何编码** |

无论上述哪种情况，最终是否调用 Embedding API 只取决于 `sha256(TEMPLATE_VERSION | embedding_text)` 是否变化，且同文本会先查 `recall_embedding_cache`。

## 2. 部署与配置

### 2.1 环境变量（新增部分，完整见 `.env.example`）

| 变量 | 默认 | 说明 |
|---|---|---|
| `EMBEDDING_PROVIDER` | `dashscope` | `fake` = 离线确定性向量（单测 / 演示，不出网） |
| `ADMIN_API_KEY` | 空 | 非空时所有写 / 管理接口必须带 `X-API-Key` 头 |
| `LLM_TIMEOUT` | 120 | LLM 请求超时秒数 |
| `AUTO_IMPORT_ON_EMPTY` | 1 | 实体库为空时自动导入 `data/database_meta.json` |
| `META_MIRROR_ENABLED` | 1 | 写操作后把实体层导出镜像为 `data/database_meta.json` |
| `DB_URL` | sqlite | `mysql+pymysql://...` 或 `sqlite:///path`（显式 sqlite 地址将被直接使用） |

### 2.2 启动

```bash
cd webapp
pip install -r requirements.txt
cp ../.env.example .env   # 填写 LLM_API_KEY / DB_URL / ADMIN_API_KEY
python -m uvicorn app.main:app --host 0.0.0.0 --port 5003
```

启动流程：初始化表结构 → 从 DB 装载实体与向量到内存 FAISS（**不编码**）→ 若实体库为空且 `AUTO_IMPORT_ON_EMPTY=1`，导入 `data/database_meta.json` 并编码一次。

### 2.3 新增数据表（自动建表）

`src_table / src_metric / src_dimension / src_dim_value / src_knowledge`（源对象）、`recall_entity`（实体 + 向量）、`recall_embedding_cache`（文本→向量缓存）、`faiss_id_map`、`agent / agent_scope`、`recall_kv`。旧的 `meta_*` 表仍会被创建但不再使用，可在确认后删除。

### 2.4 离线测试

```bash
cd webapp && python -m pytest tests/test_entity_layer.py -q     # 15 个用例，约 10s，无需外部 API
```

## 3. 接口总览

鉴权：标注 🔒 的接口在 `ADMIN_API_KEY` 非空时需请求头 `X-API-Key: <key>`，否则返回 `401`。
所有接口 `Content-Type: application/json`。

### 3.1 在线召回（供智能问数 / Java 侧调用）

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/api/recall/prod` | **生产接口**，统一 `{code,message,data}` 包装 |
| POST | `/api/recall/slim` | 全链路（改写→召回→精判→导出 database_meta） |
| POST / GET | `/api/recall` | 原始四路召回（调试） |
| POST | `/api/scope/resolve` | 预览一个 scope 会解析出多少实体 |

### 3.2 实体变更（供数据管理模块调用）

| 方法 | 路径 | 说明 |
|---|---|---|
| POST 🔒 | `/api/entities/upsert` | 增量推送：只传变化的对象 |
| DELETE 🔒 | `/api/entities/{kind}/{key}` | 删除单个源对象，kind ∈ table/metric/dimension/knowledge |
| POST 🔒 | `/api/entities/import?replace=true&force=false` | 整份 database_meta 导入（仍按 hash 增量编码） |
| POST 🔒 | `/api/entities/resync?force=false` | 按 src_* 全量重建实体（force=true 忽略缓存全部重编） |
| GET | `/api/entities/status` | 实体数 / 索引向量数 / 模型标签 / 上次同步统计 |
| GET | `/api/entities/{entity_key}` | 查单个实体（含 embedding_text、legal_tables） |

### 3.3 Agent 管理（供智能体管理模块调用）

| 方法 | 路径 | 说明 |
|---|---|---|
| PUT 🔒 | `/api/agents/{agent_id}` | 注册 / 覆盖 Agent 范围（幂等） |
| GET | `/api/agents` | 列表 |
| GET | `/api/agents/{agent_id}` | 详情 + 解析后的范围统计 |
| DELETE 🔒 | `/api/agents/{agent_id}` | 删除（不影响实体 / 向量） |

### 3.4 兼容接口（v1.x 已有，全部保留）

`/health`、`/api/metadata/stats`、`/api/metadata/list/{entity_type}`、`GET/PUT /api/metadata/database-meta`、`POST /api/metadata/rebuild`、`GET /api/metadata/rebuild/status`、`POST /api/metadata/reload-index`、`/api/config/*`、`/api/prompts/*`、`/api/rewrite/*`、`/api/enrich/*`、`/api/batch-test/*`、`/api/meta-sync/*`。行为差异见第 6 章。

## 4. 上游接口契约（本模块设计，供上游实现）

### 4.1 数据管理模块 → 召回服务

**触发时机**：表 / 指标 / 维度 / 维度值 / 知识 在数据管理模块中被 新增 / 修改 / 删除 后，**同步或异步**调用一次。只传变化的对象；批量变更可合并成一次请求。

```
POST /api/entities/upsert
X-API-Key: <ADMIN_API_KEY>
```

```json
{
  "tables": [
    {
      "table_name": "view_gdl",
      "display_name": "供电量表-市级区级供电量表",
      "description": "……",
      "columns": [
        {"column_name": "daypowersupply", "data_type": "text", "is_measure": true, "is_dimension": false, "description": "日供电量", "agg_type": "sum"},
        {"column_name": "org_name", "data_type": "varchar", "is_measure": false, "is_dimension": true, "description": "供电局名称"}
      ]
    }
  ],
  "metrics": [
    {"metric_code": "daypowersupply", "metric_name": "日供电量", "description": "", "unit": "亿千瓦时", "data_type": "text", "caliber_scope": "", "aliases": ["日供电"]}
  ],
  "dimensions": [
    {"dimension_code": "org_name", "dimension_name": "供电局名称", "description": "", "data_type": "varchar", "aliases": [],
     "possible_values": ["宝安供电局", "南山供电局"]}
  ],
  "dim_values": [
    {"dimension_code": "org_name", "mode": "upsert", "values": ["龙华供电局", {"value_name": "光明供电局", "synonyms": "光明"}]}
  ],
  "knowledge": [
    {"knowledge_id": "k_001", "knowledgeAlias": "线损率", "knowledgeElement": "线损率 = 线损电量 / 供电量"}
  ],
  "deletes": {"tables": [], "metrics": ["old_code"], "dimensions": [], "knowledge": []},
  "force": false
}
```

字段约定：

- 所有对象字段与现有 `database_meta.json` 同构，上游可直接复用现有导出逻辑。
- `dimensions[].possible_values` 出现时 **整体替换** 该维度的值；仅想增删个别值用 `dim_values`，`mode` ∈ `upsert | replace | delete`。
- `deletes` 与 upsert 可同请求；先删后增。
- 删除单对象也可用 `DELETE /api/entities/metric/{metric_code}`。

响应：

```json
{"ok": true, "built": 40, "encoded": 1, "cache_hits": 0, "unchanged": 39, "removed": 0,
 "embed_model": "text-embedding-v4@1024", "template_version": "v2", "elapsed_ms": 812,
 "affected": {"tables": 0, "metrics": 1, "dimensions": 0, "knowledge": 0}}
```

- `built`：本次重新构造并做 hash 校验的实体数（含传播）；`encoded`：真正调用 Embedding 的数量；`unchanged`：hash 未变跳过；`removed`：删除的实体数。
- 同一内容重复推送 `encoded=0`，接口幂等，上游可放心重试。

**首次全量 / 对账**：`POST /api/entities/import?replace=true`，body 为整个 `database_meta` 对象（`{"table_summaries":[...],"available_metrics":[...],"available_dimensions":[...],"business_context":[...]}`）。`replace=true` 会删除上游未包含的源对象。

### 4.2 智能体管理模块 → 召回服务

**触发时机**：Agent 创建 / 修改绑定关系 / 删除。**不会触发向量化**，毫秒级返回。

```
PUT /api/agents/{agent_id}
X-API-Key: <ADMIN_API_KEY>
{
  "agent_name": "供电量分析助手",
  "scope": {
    "tables": ["view_gdl", "view_xs"],      // 必填之一：允许访问的表
    "metrics": [],                          // 可选：在表范围内再收窄到这些指标 code
    "dimensions": []                        // 可选：同上
  }
}
→ {"ok": true, "agent_id": "agent_01", "version": 3,
   "resolved": {"unrestricted": false, "label": "agent:agent_01@3", "n_tables": 2, "n_metric": 12, "n_dimension": 6, "n_dim_value": 88},
   "warnings": {"unknown_tables": ["view_not_exist"]}}
```

范围语义：`tables` 非空 → 这些表 + 表下全部指标 / 维度 / 维度值；`metrics` / `dimensions` 非空 → 在此基础上进一步收窄；三者全空 = 不限制。`warnings` 提示引用了尚不存在的表 / code（不报错，后续数据推送到位后自动生效）。

### 4.3 智能问数在线侧 → 召回服务

在现有 `/api/recall/prod`（或 `/api/recall/slim`）请求体上**追加一个可选字段**：

```json
{"query": "宝安昨天的供电量", "agent_id": "agent_01"}
```

- 不传 `agent_id` → 行为与 v1.x 完全一致（全库）。
- `agent_id` 不存在 → `/api/recall/prod` 返回 `{"code": 404, "message": "智能体不存在：xxx", "data": null}`；`/api/recall/slim` `/api/recall` 返回 HTTP 404。
- 也可不注册 Agent，直接传 `"scope": {"tables": [...]}` 内联范围（优先级高于 `agent_id`）。
- 响应 `data` 里新增 `scope` 摘要与 `agent_id` 回显；`database_meta.available_metrics[].tables` 已按范围裁剪。

## 5. 详细接口说明

### 5.1 `POST /api/recall/prod`

请求：`{"query": str, "agent_id"?: str, "scope"?: ScopeSpec}`（改写 / 精判开关由 `PROD_USE_*` 环境变量决定，不受调用方控制）。

响应：`{"code": 200, "message": "ok", "data": {"query", "agent_id", "scope", "database_meta": {...}, "timings": {...}}}`；错误码 `400` 参数错误、`404` agent 不存在、`500` 内部错误。

### 5.2 `POST /api/recall/slim`

请求字段：`query`（必填）、`parallel`、`include_business_context`、`dim_value_topn`、`use_rewrite`、`use_rewrite_llm`、`use_llm_judge`、`intent_split`、`out_table`、`out_metric`、`out_dimension`、`agent_id`、`scope`。
响应：`{query, rewrite, recall, judge, database_meta, scope, timings}`。

### 5.3 `POST /api/recall`

请求：`{"query", "use_llm_judge", "parallel", "agent_id", "scope"}`。
响应：`{query, clean_query, time_terms, candidates[], by_path{}, timings_ms, scope, llm_judge?}`；`candidates[]` 每项含 `entity_type, entity_id, entity_key, entity_name, display_name, description, score, source, table_id, dimension_id, legal_tables[]`（`legal_tables` 已按范围裁剪为表的 entity_id 列表）。

### 5.4 `GET /api/entities/status`

```json
{"index": {"table": 70, "metric": 316, "dimension": 57, "dim_value": 546, "knowledge": 11, "topic": 0, "ntotal": 1000},
 "entities": {...同上...}, "catalog_version": 12, "embed_model": "text-embedding-v4@1024",
 "template_version": "v2", "last_result": {...上次 apply 统计...}}
```

### 5.5 `GET /api/agents/{agent_id}`

```json
{"agent_id": "agent_01", "agent_name": "…", "version": 3, "updated_at": "…",
 "scope": {"tables": [...], "metrics": [...], "dimensions": [...]},
 "resolved": {"unrestricted": false, "n_tables": 2, "n_metric": 12, "n_dimension": 6, "n_dim_value": 88}}
```

### 5.6 `POST /api/scope/resolve`

请求 `ScopeSpec`，响应 `{"unrestricted", "label", "n_tables", "n_metric", "n_dimension", "n_dim_value", "tables": [...]}`。用于 Agent 管理页"预览范围"。

## 6. 对外接口变更说明（v1.x → v2.0）

> 原则：与其他系统对接的接口 **全部保留路径与原有字段**，只做向后兼容的追加；下列是必须说明的差异。

| 接口 | 变更类型 | 说明 | 调用方需要做什么 |
|---|---|---|---|
| `POST /api/recall/prod` | 追加字段 | 请求新增可选 `agent_id`、`scope`；响应 `data` 新增 `agent_id`、`scope`；新增错误码 `404`（agent 不存在）；`available_metrics[].tables` 新增 | 无需改动；接入 Agent 范围时传 `agent_id` |
| `POST /api/recall/slim` | 追加字段 | 同上；agent 不存在返回 HTTP 404 | 无需改动 |
| `POST/GET /api/recall` | 追加字段 | 请求新增 `agent_id`、`scope`；候选新增 `entity_key`、`entity_name`、`rerank_score`；响应新增 `scope`、`recall_text`、`intent_subs` | 无需改动 |
| `POST /api/metadata/rebuild` | **语义变化** | 原为"读 database_meta.json 全量重建向量"；现为"按 DB 源对象增量重建，仅重编变化实体"。新增参数 `force=true`（强制全量重编）、`import_file=true`（先重新导入 data/database_meta.json） | 若期望旧行为，调用 `?import_file=true&force=true` |
| `PUT /api/metadata/database-meta` | **语义变化** | 原为写回 json 文件 + 热重载映射；现为导入源对象 + 增量重建（`rebuild=false` 可只落库） | 无需改动；注意现在会触发编码（仅变化部分） |
| `POST /api/metadata/reload-index` | 语义微调 | 从 DB 重新装载实体与向量到内存（不编码） | 无 |
| `GET /health` | 字段变化 | `index` 段改为 `{ntotal, per_type, catalog_version, embed_model}` | 若解析了旧 `index` 字段需适配 |
| `GET /api/metadata/stats` | 追加字段 | 新增 `derived_metrics`、`topics` 计数 | 无 |
| 所有写 / 管理接口 | **鉴权** | `ADMIN_API_KEY` 非空时需 `X-API-Key` 头，否则 `401`。涉及：`/api/metadata/rebuild`、`reload-index`、`PUT database-meta`、`/api/config/*` 写、`/api/prompts/*` 写、`/api/enrich/*`、`/api/meta-sync/*`、`/api/entities/*` 写、`/api/agents/*` 写 | 调用方配置密钥；开发环境可留空关闭 |
| `/api/enrich/apply` | 内部实现变化 | 接受的补全结果经实体层增量写入，响应新增 `sync` 统计 | 无 |
| `/api/batch-test/run` | 追加字段 | 请求新增 `agent_id`、`scope` | 无 |

**未变化**：`/api/config/*`、`/api/prompts/*`、`/api/rewrite/*`、`/api/metadata/list/*`、`/api/metadata/domain-knowledge`、`/api/batch-test/*` 的路径与响应结构。

## 7. 运维操作速查

| 场景 | 操作 |
|---|---|
| 首次部署 | 放好 `data/database_meta.json`，启动即自动导入编码 |
| 换 Embedding 模型 / 维度 | 改 `EMBEDDING_MODEL`/`EMBEDDING_DIM`，重启后 `POST /api/entities/resync?force=true` |
| 改了实体文本模板（`builder.py`） | 提升 `TEMPLATE_VERSION`，重启后 `resync`（自动检测 hash 变化） |

| 怀疑内存索引与 DB 不一致 | `POST /api/metadata/reload-index` |
| 查看某实体到底被编成什么文本 | `GET /api/entities/metric:daypowersupply` |
| 前端 | 左侧"Agent 管理"页可增删 Agent、预览范围、查看实体层状态并触发增量 / 全量重建；召回测试与批量测试页可选 Agent；写操作 401 时会弹窗要求输入管理密钥（保存于浏览器本地） |

## 8. v2.0 真实环境验证记录（2026-09-29）

环境：DashScope `text-embedding-v4@1024`、SQLite、`PROD_USE_*` 默认（改写开 / LLM 改写关 / 精判关）、并发 5。

### 8.1 首次导入与增量行为

| 场景 | 结果 |
|---|---|
| 首次导入 `data/database_meta.json` | 1000 实体，编码 908 次（92 条重复文本自动去重），81 s |
| 重启服务 | 从 DB 装载 1000 向量，0.7 s，**0 次编码** |
| 原样重推一个指标 | `encoded=0, unchanged=39` |
| 改一个指标 description | `built=39, encoded=1, unchanged=38`，534 ms |
| 改回原描述 | `encoded=0, cache_hits=1`（命中向量缓存） |
| 新增一个维度值 | `encoded=1`（仅该值；维度本体文本命中缓存） |
| 删除该维度值 | `removed=1, encoded=0` |
| 注册 Agent（绑定 view_gdl） | 毫秒级返回，`catalog_version` 不变，0 次编码 |
| `agent_id` 召回 | 候选全部落在 view_gdl；`slim` 导出 `table_summaries=[view_gdl]`，`available_metrics=[日供电量 → tables:[view_gdl]]` |

### 8.2 批量测试基线（`tests/data/测试问题_llm.xlsx`，223 题）

| 维度 | 命中 | 命中率 |
|---|---|---|
| **整体（四列全中）** | 211 / 223 | **94.6 %** |
| 指标 | 203 / 212 | 95.8 % |
| 表 | 217 / 223 | 97.3 % |
| 维度 | 215 / 215 | 100 % |
| 维度值 | 200 / 200 | 100 % |
| 单题耗时 | p50 1.09 s · p90 1.84 s · max 2.93 s | |

未命中 12 题集中在 6 个实体：`采集指标总在线率 / view_elec_trading_summary`（4 题）、`分线合格率`（2）、`现货完整率`（2）、`线路总条数`（2）、`用电负荷`（1）、`分台总合格数`（1）。这些实体均存在于元数据中但描述为空、名称与问句字面差异大，属于《召回效果提升方案》中"描述补全 / 词法召回"范畴，与本次架构改造无关。此结果作为 v2.0 回归基线，后续改动命中率低于 94 % 需排查。
