# 视图管理接口文档

## 产品流程

视图管理的核心任务是将一条业务 SQL 注册为可供分析使用的"视图"，并管理其字段元数据。

**新建视图流程：**

1. 用户输入 SQL 和数据源，点击"解析" → 系统执行 SQL（WHERE 1=0）获取字段名和类型
2. 用户填写视图中英文名，确认字段列表 → 提交注册
3. 系统创建视图记录，录入字段映射，根据字段类型自动推测指标/维度

**编辑视图流程：**

1. 用户打开已有视图 → 系统回显当前配置（名称、SQL、字段列表）
2. 用户修改 SQL，点击"解析" → 系统弹出确认提示：
弹出框内容：
   本次重新解析会自动匹配新旧输出字段：
   · 【保留】：该字段标识（fieldKey）与修改前一致，系统保留已填写的指标 / 维度映射关系；
   · 【新增】：本次 SQL 解析新增输出字段，后续需要手动补充中文名和映射配置；
   · 【废弃】：本次SQL 解析后已不输出的字段，页面标记为废弃，保存后该字段会从该视图移除，其指标维度映射关系也会同步移除。
确认要执行解析吗？
按钮区域：【取消】、【确认解析】

3. 用户确认 → 系统重新执行 SQL 并与已有字段映射对比，标记每个字段的状态：
   - **保留（0）**：新老 SQL 中都存在的字段，保持原有注册信息
   - **新增（1）**：新 SQL 中出现的字段，需要重新设置映射
   - **废弃（2）**：旧 SQL 中存在但新 SQL 中已消失的字段，标记删除
4. 用户确认结果 → 提交保存，系统按状态分别处理每个字段

## 接口列表

### 1. 解析 SQL 字段

```
POST /v1/field-mappings/tables/parse
```

**请求体：**

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| sourceId | Long | 是 | 数据源 ID |
| tableId | Long | 否 | 表 ID，编辑时传入用于对比已有映射 |
| sql | String | 是 | 待解析的 SQL 语句 |

```json
{
  "sourceId": 1,
  "tableId": 10,
  "sql": "SELECT id, name, amount FROM order_info WHERE status = 1"
}
```

**响应：**

```json
{
  "code": 200,
  "data": [
    {
      "fieldKey": "id",
      "fieldName": "订单ID",
      "fieldType": "bigint",
      "compareStatus": "0"
    },
    {
      "fieldKey": "name",
      "fieldName": "订单名称",
      "fieldType": "varchar(64)",
      "compareStatus": "0"
    },
    {
      "fieldKey": "amount",
      "fieldName": "金额",
      "fieldType": "decimal(20,4)",
      "compareStatus": "0"
    },
    {
      "fieldKey": "status",
      "fieldName": "状态",
      "fieldType": "varchar(32)",
      "compareStatus": "2"
    },
    {
      "fieldKey": "created_at",
      "fieldName": "created_at",
      "fieldType": "datetime",
      "compareStatus": "1"
    }
  ]
}
```

**说明：**

- `fieldName` 初始值为 `fieldKey`，编辑模式（传入 tableId）下已有字段会回填中文名
- `compareStatus`：编辑模式有值（0-保留 1-新增 2-废弃），新建模式无此字段
- `fieldType` 由 JDBC 驱动的 ResultSetMetaData 返回

```
GET /v1/field-mappings/tables/view/info?id={id}
```

**响应：**

```json
{
  "code": 200,
  "data": {
    "sourceId": 1,
    "viewEnName": "view_order_summary",
    "viewCnName": "订单汇总视图",
    "sql": "SELECT id, name, amount, status FROM order_info",
    "columns": [
      {
        "fieldKey": "id",
        "fieldName": "订单ID",
        "fieldType": "bigint"
      },
      {
        "fieldKey": "name",
        "fieldName": "订单名称",
        "fieldType": "varchar(64)"
      },
      {
        "fieldKey": "amount",
        "fieldName": "金额",
        "fieldType": "decimal(20,4)"
      }

  }
```

**说明：**

- 只回显当前已保存的字段映射，无 `compareStatus`

### 3. 注册/保存视图

```
POST /v1/field-mappings/tables/register-view
```

**请求体：**

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| id | Long | 否 | 视图 ID，更新时传入，新建不传 |
| sourceId | Long | 是 | 数据源 ID |
| viewEnName | String | 是 | 视图英文名，须以 `view_` 开头 |
| viewCnName | String | 是 | 视图中文名 |
| sql | String | 是 | 视图 SQL |
| columns | List\<ParseColumnVO\> | 是 | 字段列表 |

```json
{
  "id": 10,
  "sourceId": 1,
  "viewEnName": "view_order_summary",
  "viewCnName": "订单汇总视图",
  "sql": "SELECT id, name, amount, created_at FROM order_info",
  "columns": [
    {
      "fieldKey": "id",
      "fieldName": "订单ID",
      "fieldType": "bigint",
      "compareStatus": "0"
    },
    {
      "fieldKey": "name",
      "fieldName": "订单名称",
      "fieldType": "varchar(64)",
      "compareStatus": "0"
    },
    {
      "fieldKey": "amount",
      "fieldName": "金额",
      "fieldType": "decimal(20,4)",
      "compareStatus": "0"
    },
    {
      "fieldKey": "status",
      "fieldName": "状态",
      "fieldType": "varchar(32)",
      "compareStatus": "2"
    },
    {
      "fieldKey": "created_at",
      "fieldName": "created_at",
      "fieldType": "datetime",
      "compareStatus": "1"
    }
  ]
}
```

**响应：**

```json
{
  "code": 200,
  "data": {
    "id": 10
  }
}
```

**后端处理逻辑：**

| id | compareStatus | 含义 | 处理 |
|----|--------------|------|------|
| null | 无 | 新建视图 | 全量 insert，推测 basicTypeKey |
| 有 | 0/1/2 | 编辑-已重新解析 | 按状态精细化处理 |
| 有 | 无 | 编辑-未解析（SQL 未变动） | 仅更新视图元信息，不动字段映射 |

**更新时按 compareStatus 的处理：**

| compareStatus | 处理 |
|---------------|------|
| 0（保留） | 更新已有记录的 fieldType/fieldName，保留 basicId 等注册信息 |
| 1（新增） | insert 新记录，推测 basicTypeKey |
| 2（废弃） | 已有记录 status 设为 0（删除） |

**说明：**

- 新建时根据字段类型自动推测 basicTypeKey（int/decimal/float/double → 指标，varchar/char/date/time → 维度）
- 编辑时仅当 columns 中带了 compareStatus 才处理字段映射，否则认为 SQL 未变动，只更新表级信息
- 保留字段的注册信息不会丢失

## 完整前端交互示例

### 新建视图

```
步骤 1: POST /v1/field-mappings/tables/parse
入参: { "sourceId": 1, "sql": "SELECT ..." }
返回: [{ fieldKey, fieldName, fieldType }]  ← 无 compareStatus

步骤 2: 用户填写中英文名，确认字段 → POST /v1/field-mappings/tables/register-view
入参: { sourceId, viewEnName, viewCnName, sql, columns: [上一步返回的列表] }
返回: { id: 10 }
```

### 编辑视图

```
步骤 1: GET /v1/field-mappings/tables/view/info?id=10
返回: { sourceId, viewEnName, viewCnName, sql, columns: [{ fieldKey, fieldName, fieldType }] }

步骤 2: 用户修改 SQL → POST /v1/field-mappings/tables/parse
入参: { "sourceId": 1, "tableId": 10, "sql": "SELECT ..." }
返回: [{ fieldKey, fieldName, fieldType, compareStatus: "0"|"1"|"2" }]

步骤 3: 用户确认 → POST /v1/field-mappings/tables/register-view
入参: { id: 10, sourceId, viewEnName, viewCnName, sql, columns: [上一步返回的列表] }
返回: { id: 10 }
```
